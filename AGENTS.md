# AGENTS.md

The pixijs.com website: PixiJS 2D and 3D docs, guides, examples, blog, and showcase, built with Docusaurus. `README.md` covers the scripts and layout.

## Read before you start

- **`.repos/`**, read-only source of the libraries the site documents: `.repos/pixijs` is pixi.js, `.repos/filters` is pixi-filters and `.repos/pixi-3d` is `@pixi/3d`, each at the commit the installed build came from. Read it for how they work inside, in place of `node_modules/*/lib`. Run `npm run sync:repos` first; it clones what's missing, moves a checkout after an upgrade, and is a no-op otherwise. Search it by path, since repo-wide searches skip it. pixi-3d is private: without access `.repos/pixi-3d` is absent and the 3D docs build as three placeholder guides.
- **Generated content**: the v8 guides in `docs/guides/{concepts,components,migrations}`, the examples, the assets in `static-pixi/`, the guides sidebar and `static/llms.txt` are gitignored output of `npm run generate:pixi`, built from `.repos/pixijs` before types, start, build and deploy. Local edits get overwritten; fix the source upstream in pixijs/pixijs (`src/**/__docs__/`, `examples/`, `examples/assets/`). Site-owned: `docs/guides/{getting-started,third-party}`, `blog/examples`, `static/examples/previews` and `static/assets`, which only holds what pixi doesn't.
- **Generated 3D content**: `docs-3d/guides/`, the 3D tutorial pages in `docs-3d/tutorials/`, `src/tutorials/generated-3d/`, `static-pixi-3d/` and the `*-3d.json` files in `src/data/generated/` come from `.repos/pixi-3d` via `npm run generate:pixi-3d`; fix them upstream in pixijs/pixi-3d (`src/**/__docs__/`, `examples/site/`, `tutorials/`). Site-owned: `docs-3d/examples/index.mdx`, `docs-3d/tutorials/index.md` and `static/examples/previews/3d`. `scripts/libraries.mts` holds the per-package settings, including every 3D guide's URL. `static-runtime/` and `src/data/generated/runtime.json` are the editor's import map files, from `npm run generate:runtime`.
- **Pixi version**: the `pixi.js` version in `package-lock.json` is the only version source. `.github/workflows/sync-pixi.yml` bumps it after each stable pixi release and opens a `sync/pixi` PR. By hand: `npm install pixi.js@^X.Y.Z`, `npm run generate:pixi`, then `npm run generate:example-previews -- --missing` for new examples.
- **@pixi/3d version**: until it's on npm, `vendor/pixi-3d.tgz` is the only version source, and its `package.json` `gitHead` names the pixi-3d commit. `.github/workflows/sync-pixi-3d.yml` re-vendors it and opens a `sync/pixi-3d` PR. By hand: `npm run vendor:pixi-3d -- <clean pixi-3d checkout>`, `npm run generate:pixi-3d` (prefix `PIXI_3D_REPO=<checkout>` when the commit isn't pushed), then `npm run generate:example-previews -- --pkg 3d --missing`. The vendor script builds inside the checkout it's given, so point it at a clean clone, not a checkout someone is working in.
- **Where things live**: the shell (rail, top nav, search dialog, version menu) in `src/shell/`, wired in by `src/theme/Layout` and, on docs pages, `src/theme/DocRoot/Layout`; tokens in `src/css/tokens.scss`; primitives in `src/components/ui/`; GSAP and motion hooks in `src/motion/`; the homes in `src/components/Home/`; the editor in `src/components/Editor/` running on the import-map runner in `src/runtime/` (`scripts/runtime.mts` writes its import map). README's "Site Shell" section has the rules: layout CSS never keys on `<html>` classes, which react-helmet-async rewrites while hydration runs (app pages are `html:has([data-app-page])`), icons come from the `ui/Icon` sprite (add the lucide path there; `lucide-react` isn't installed), and GSAP is imported only from page components, never the shell.

## Verify

- `npm run lint` and `npm run types`.
- For page or shell changes: `npm run build` (it generates first; `docusaurus build` alone leaves generated pages stale), `npm run serve -- --port <port>`, then `node scripts/verify/urls.mjs scripts/verify/url-baseline.txt build` (must print `0 missing, 0 dangling`) and `node scripts/verify/visual.mjs --base http://localhost:<port> --only <routes> --exact`. Look at the screenshots.
- When the pinned pixi-3d commit isn't pushed, `export PIXI_3D_REPO=<pixi-3d checkout>` before any npm command, or the 3D docs build as placeholders.
