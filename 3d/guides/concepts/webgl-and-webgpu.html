WebGL and WebGPU

PixiJS 3D draws with whichever GPU renderer PixiJS starts, WebGPU or WebGL2. Scenes, materials, lights and events use the same API on both.

Choosing a renderer​

Ask for WebGPU with PixiJS's preference option. PixiJS starts WebGPU where the browser has it and falls back to WebGL2 where it doesn't. If you leave preference out, PixiJS tries WebGL2 first, even in a browser that has WebGPU.

On WebGPU, PixiJS 3D needs a GPU with the 'indirect-first-instance' feature. On a GPU without it, app.init throws instead of falling back to WebGL2. To fall back on those GPUs too, check for the feature before you start:

import { Application, RendererType } from 'pixi.js';

const app = new Application();
const adapter = await navigator.gpu?.requestAdapter();

await app.init({
  preference: adapter?.features.has('indirect-first-instance') ? 'webgpu' : 'webgl',
  resizeTo: window,
});

const isWebGPU = app.renderer.type === RendererType.WEBGPU;

app.renderer.type tells you which renderer started. To try a scene on WebGL2 in a browser that has WebGPU, start PixiJS with preference: 'webgl'.

Installation covers how each renderer's code loads, and what to import when you start PixiJS with skipExtensionImports: true.

Renderer differences​

These are the differences you're most likely to meet:

  • Your own shader code. A ShaderBit holds its code twice, gpu in WGSL for WebGPU and gl in GLSL for WebGL2. Write both. A bit that lacks one runs none of its code on that renderer, and you get no error. Toon and custom materials shows both.
  • Glass. On WebGL2, glass refracts nothing in a view that draws straight onto an opaque canvas, which is what PixiJS does by default. Either PixiJS's useBackBuffer: true option or the view's composite: true fixes it. How glass draws covers both and says when to pick each.
  • Float textures. Some features draw into floating-point textures. One is a cube map, six images of the surroundings, used as the view's environment. Another is any post effect whose stage is 'beforeToneMapping', the default for bloom and most other built-in effects. On WebGL2, PixiJS 3D draws into these textures only when the device has the EXT_color_buffer_float extension, and rendering throws on a device without it. Leave these features out on such a device. How a frame renders shows the check. Without the extension, a Hemisphere environment still lights the scene but loses its reflections, so a metal surface with no other light on it turns black.
  • Polygon offset. A material's state.polygonOffset won't reliably keep a mark, such as a skid mark, in front of the surface it's drawn on. WebGPU ignores it. On WebGL2, a negative offset can push a mark behind a floor seen at an angle. Leave it at 0 and lift the mark's geometry a little off the surface instead. That works on both renderers.

How each renderer culls​

Culling skips meshes outside the camera's frustum, the volume of space the camera sees, so the GPU never draws them. The view's cull mode is 'gpu' by default. In that mode, where the test runs depends on the renderer and the browser:

  • WebGPU tests the meshes in a compute shader, a GPU program that calculates rather than draws.
  • WebGPU in Safari, and in any browser on an iPhone or iPad, tests them on the CPU instead. That holds for a typical scene, and even for a BatchedMesh3D of ten thousand trees whose cull is 'gpu'. There, only a far larger batch culls in the compute shader.
  • WebGL2 has no compute shaders, so it tests on the CPU in 'gpu' mode, the same as in 'cpu' mode.
  • Blended meshes, whose material has an alphaMode of 'blend', are tested on the CPU on both renderers.

When culling runs on the CPU, it tests every mesh every frame, even when nothing moves, so its cost grows with the number of meshes. CullMode says when to use each mode.

Batching and culling sets Camera3D.cullFrustum to the frustum of a scout camera that sweeps round a field of clay pieces, so you can watch culling from outside that camera. Its pane switches cull between 'off', 'cpu' and 'gpu' and counts the pieces that survive.
