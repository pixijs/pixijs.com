Introducing PixiJS 3D

ZyiePixiJS Admin

PixiJS 3D is here, and it's in open beta today.

Rendered in real time by PixiJS 3D.

PixiJS is now a full 2D engine and a full 3D engine at once. Both share one stage, and both are fast by default.

If you already build with PixiJS, add one View3D to your project and you're in 3D, with the addChild, Assets, and pointer events you already know. If you're new to PixiJS, this is a good place to start.

  • 2D and 3D share a stage. A 3D scene is a display object. Add one or several anywhere in your 2D scene.
  • It's fast by default. Write a scene the obvious way and it's quick. We benchmarked the different ways to render, and the engine picks the best one for your device, browser, and scene.
  • The essentials are built in. Shadows, animation, particles, post-processing, and the rest of what you'd expect from a 3D engine are all here.
  • It's WebGPU first. We designed it around WebGPU, and the same code runs on WebGL2 for everyone else.
  • It's AI ready. Build with your coding agent using new PixiJS skills for 2D and 3D.
  • It's free. It's MIT licensed, and it always will be.

A new dimension for the project you already have​

You don't port anything, and you don't run a second engine next to PixiJS. A 3D scene is a display object. Load a model, build a View3D from it, and add it to the stage:

import { View3D } from '@pixi/3d';
import { Assets } from 'pixi.js';

const source = await Assets.load('helmet.glb');
const view3d = View3D.from(source);

app.stage.addChild(view3d);

The view layers with everything else you draw, so you choose how much 3D you want. Keep your regular 2D workflow and drop in a 3D element where it helps, like a spinning trophy in a menu or a character in a shop screen. Or make one View3D fill the screen, build a whole 3D game inside it, and put your UI over the top as a regular 2D container.

Everything in between works too. Filters and masks work on a 3D view. 3D objects take the same pointer events as sprites. glTF models load through Assets. Your 2D can follow your 3D, like a health bar over a character.

A View3D is a display object, so you can put as many as you want in one 2D scene. Each has its own scene and camera, and you place and size each one like a sprite.

The 3D sees the 2D around it too. This logo is 3D glass, and it bends the 2D poster drawn behind it. Drag the logo to turn it:

It goes the other way too. You can draw any 2D container onto a 3D surface, live. Here a 2D scene with a bouncing wordmark and a clock runs on the screen of a 3D monitor:

And since a View3D is a display object, that 2D container can hold one of its own. So the two nest, as many levels deep as you like. A 3D scene can show a 2D container that holds another 3D scene.

The shelf of demos at goodstuff.pixijs.io is built this way. Each of its screens is a 2D scene drawn onto a curved 3D panel.

View3D and 2D content shows how far the two mix.

Fast by default​

PixiJS has always tried to make the default way of using it the fast way, and 3D is no different. You write a scene the obvious way, and it's fast.

Add five cubes that share a geometry and a material, and they draw in one instanced call. You didn't ask for that, and you shouldn't have to. The engine can see that those cubes batch, so it batches them.

There's more to a renderer than instance counts, though. A real scene is many different things. It has different models and materials, characters that animate, lights that cast shadows, and a HUD over the top, and much of it changes from frame to frame. That's the kind of scene we spent our time on, so PixiJS 3D is fast in a real game as well as in a benchmark.

Part of that is accepting that no single way of drawing a scene is the fastest everywhere. What's quickest on a desktop GPU isn't always quickest on an iPhone, and a small scene wants different treatment from a huge one. So we benchmarked the different ways to render, and the engine picks the best path for your device, your browser, and your scene.

Culling shows how that plays out. On most WebGPU browsers it runs in a compute shader. In Safari, and on any iPhone or iPad, it runs on the CPU for a typical scene and moves to the compute shader once a batch gets big enough. You write the same code either way, and you never see the switch.

The engine also updates only the meshes that changed, so a scene that holds still costs the CPU little. These 100 crates in 100 colors are one draw call, and nothing in the code asks for that:

import { CubeGeometry, Material3D, Mesh3D } from '@pixi/3d';

const geometry = new CubeGeometry();

for (let i = 0; i < 100; i++) {
    const crate = new Mesh3D({
        geometry, // one geometry for every crate
        material: new Material3D({ baseColor: Math.random() * 0xffffff, roughness: 0.6 }),
    });

    crate.position.set((i % 10) * 1.5, 0.5, Math.floor(i / 10) * 1.5);
    view3d.root.addChild(crate);
}

The big numbers are there when you want them. For a forest or a crowd, BatchedMesh3D draws tens of thousands of copies from one node. This is 100,000 objects with shadows, all at 60 fps:

The performance guide has the details.

A modern architecture for a modern web​

WebGPU is where the web is going, so we designed PixiJS 3D around it. We had a head start. We built PixiJS v8 with this in mind, so most of the groundwork was already done, and 3D adds the newer techniques on top of it.

It uses render bundles, indirect draws, and culling in a compute shader. We adopted a technique only where we measured it to be faster and browsers already support it.

Culling in a compute shader wasn't possible before WebGPU. It speeds up large scenes and leaves the CPU free for your game.

WebGL2 got the same attention. We optimized that side of the engine just as hard, so every game works while the web moves to WebGPU.

The same scene code runs on both, and each browser downloads only the backend it uses. Ask for WebGPU when you start the app, and PixiJS falls back to WebGL2 where it's missing:

await app.init({ preference: 'webgpu' });

The essentials are built in​

Everything you'd expect from a 3D engine is here.

You get glTF models with skinning, morph targets, animation, and compressed textures. Materials are PBR, Phong, flat, or toon, or you can write your own, including multi-pass materials. There's a render graph, HDR, tone mapping, post-processing, particles, shadows, and cascaded shadows. We've tuned each of them for speed.

Turning something on is an option you set. This is a sun that casts cascaded shadows:

const sun = new DirectionalLight({
    intensity: 3,
    castShadow: true,
    shadow: { cascades: 3 }, // sharp shadows near the camera, however big the world is
});

The engine is built to be extended too. When you need something it doesn't have, you can write your own materials, shader code, and post effects, or build a custom render graph.

Made for games​

We built PixiJS 3D to make games. Twelve animated characters from one model file draw in one call. Your HUD, menus, and touch controls are PixiJS 2D on the same stage, so there's no DOM overlay to keep in sync and no second UI library to learn.

We made two games on it too. Nightward is a survival game set in a moonlit graveyard. You only move. Six weapons fire on their own while the horde grows, until the Grave Reaper rises from the crypt. Its pixel-art sprites stand in a 3D scene as lit billboards that cast shadows, with bloom, tilt-shift, and fog over the top. The game draws its art and makes its music in code, so it loads no image or audio files:

Mach 2 is a half-pipe runner. You steer round the pipe, jump, and collect cubes through five zones, with a PixiJS 2D HUD over the run. It plays on WebGPU or WebGL2, with a keyboard or on a phone:

Both games are on Good Stuff, where we'll keep adding our 3D experiments.

To see how a full game fits together, play our racing game in the examples and read its source. The shooting gallery tutorial builds a small game step by step in a live editor.

Ready for your AI agent​

PixiJS 3D works well with agents. We built a lot with them while making it, and they pick up the API quickly. From that work we wrote the PixiJS skills, which help your agent further.

Fast by default helps agents too. An agent writes a scene the obvious way, and the engine does the batching and culling itself, so the apps your agent builds run fast without it knowing any tricks.

The pixijs-3d skill ships with PixiJS 3D. It has a complete starting app and a runnable recipe for each job, such as loading a glTF model or adding post-processing. It also lists the mistakes that throw no error but draw the wrong picture.

One command installs it next to the PixiJS skill, in Claude Code, Cursor, Codex, or Copilot:

npx skills add https://github.com/pixijs/pixijs-skills

The skill also ships inside the npm package, so it always matches the version you installed, and the 3D docs are published as llms.txt. See pixijs.com/llms for everything PixiJS has for AI tools.

Start building today​

Install it next to pixi.js:

npm install pixi.js @pixi/3d

@pixi/3d needs pixi.js 8.23.0 or later. Import it before app.init runs, add a View3D to the stage, and you have a scene. This one is a lit cube that you can drag to orbit:

import { CubeGeometry, DirectionalLight, Material3D, Mesh3D, View3D } from '@pixi/3d';
import { OrbitCamera } from '@pixi/3d/extras';
import { Application } from 'pixi.js';

const app = new Application();

await app.init({ preference: 'webgpu', background: '#1a1a2e', resizeTo: window, antialias: true });
document.body.appendChild(app.canvas);

// A View3D draws a 3D scene. Its environment lights the scene from above and below
const view3d = new View3D({ autoResize: true, environment: { skyColor: 0xc9d6ff, groundColor: 0x3a2f45 } });

app.stage.addChild(view3d);

// A red cube, and a sun shining on it
const cube = new Mesh3D({ geometry: new CubeGeometry(), material: new Material3D({ baseColor: 0xdd4444 }) });
const sun = new DirectionalLight({ intensity: 3 });

sun.position.set(-3, 5, 2);
view3d.root.addChild(cube, sun);
sun.lookAt(cube.position);

// Move the camera back, and let a drag orbit it around the cube
view3d.camera.position.set(0, 1.5, 4);
new OrbitCamera({ view: view3d });

app.ticker.add((time) => {
    cube.rotation.y += 0.01 * time.deltaTime;
});

Have fun, and help us get to 1.0​

Before today, PixiJS 3D ran as a closed beta. Our testers sent in over 30 bug reports and feature requests, and most of them made it into this release. A few were memorable. Blender exports crashed the glTF loader, and on some Android phones the shaders asked for more uniforms than WebGL2 allows, so the scene drew as a very fast, very empty screen. Thank you to everyone who poked at it and told us what broke.

Now it's your turn, and the job is mostly fun. Build a game. Put a spinning trophy in your menu. Drop a 3D teapot into a 2D app for no reason at all. When something breaks, confuses you, or has a name you'd change, tell us. The API can still change, so now is when your feedback makes the biggest difference. Once we've worked through it, we'll release 1.0.

  • Found a bug? Open an issue.
  • Have an idea or an opinion on the API? Post it in GitHub Discussions.
  • Made something you're proud of, or something gloriously broken? Show us on Discord.
